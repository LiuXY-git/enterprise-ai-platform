# Evaluation Center v0.1.0

Week 13（Day 85–91）的本地 CLI 发布候选。它能运行固定虚构销售 Agent，按独立规则判分，保存延迟、消耗状态和完整执行证据。版本状态以 [发布清单](../release-v0.1.0.json) 为准；`candidate` 不是已创建远端标签或 GitHub Release。

## 使用入口

- [Day 90 操作教程](../../experiments/day90/README.md)：运行 12 例、查看分类/失败规则、只读重新评分。
- [Day 89 消耗教程](../../experiments/day89/README.md)：Token 缺失处理、合成 usage 示例、显式价格算术估算。
- [版本说明](../../docs/evaluation-center-v0.1.md)：交付范围和能力限制。
- [发布验收与正式标签教程](../../scripts/day91/README.md)：完整性检查、重新验收、正式定版和 Release 正文生成。

## 指标应该怎样理解

| 指标 | 当前可用范围 | 不能得出的结论 |
| --- | --- | --- |
| 成功率 | 12 个固定场景的独立规则符合率；错误留在分母，未完成时为 null | 真实模型或生产任务成功率 |
| 延迟 | 父进程单例总耗时，含启动、重试、清理和基础证据保存 | 单次供应商推理延迟 |
| Token | usage 采集逻辑已经离线验证；fixture 没有供应商 usage，保持 null | fixture 消耗了 0 Token 或任意猜测的 Token |
| 成本 | 明确价格、模型身份、合法 usage 下的十进制定价估算 | 实际账单、所有计算费用或最新官方价格 |

模型响应是固定 fixture，本地 MCP 与 SQLite 查询真实运行。没有真实模型评测入口、网页看板、通用 Agent 适配器或生产服务身份认证。本版本不会改变平台 API 的 1.0.0 版本。

修改 Agent 后可用这些规则做回归，但当前适配器和来源哈希绑定 Day 82 固定入口。不能直接把任意代码塞进旧冻结清单；需要在新目录实现适配器、更新版本化描述，并保留旧版测试集与评分标准用于比较。
