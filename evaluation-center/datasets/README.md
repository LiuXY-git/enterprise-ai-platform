[sales-prepare-v1.0.0.json](sales-prepare-v1.0.0.json) 是 Day 86 的 12 例 fixture 回归输入；这里的 v1.0.0 是**测试数据版本**，不是 Evaluation Center 已发布的版本。

`smoke` 为前四个正常注入场景；`full` 为全部十二例。smoke 是 full 的子集，不能合计成 16 个独立用例。此集复用已知教学场景，不是隐藏测试集，也不代表模型泛化能力。

## 独立标准答案

金额按 [Day 65 原始虚构订单](../../experiments/day65/sales-data.json)手工核算，预检再用独立整数加法复核；没有调用 Agent 的 `expected_report` 或读取 Agent 回答来生成预期。

- 全月：SO-001/002/003/004，1200 + 850 + 350 + 600 = **3000.00 元，4 单**。最多显示两条，不能将 2050.00 元的明细小计当全月合计。
- 客户 C001：SO-001/003，1200 + 350 = **1550.00 元，2 单**。
- 7 月：**0.00 元，0 单**。取消订单 SO-005、8 月 SO-006、10 月 SO-007 不进入 9 月汇总。

`golden_report` 记录固定范围、匹配订单、展示订单、分币合计和引用规则；`expected.criteria` 记录结果字段；`behavior` 记录有限重试和停止原因。动态 task_id、receipt_id 不写死，引用应绑定本次有效回执。

业务 `failed/rejected/needs_clarification` 可能正是场景预期。判定将由后续评分器处理，不能简单把所有非 completed 算错，也不能只看退出码就判业务成功。

## 输入与覆盖边界

适配器固定为 `day82_prepare_fixture`。`input.case` 选择冻结代码中的固定问题；`task` 是可读说明，不会作为任意自由问题传给模型。`scenario` 是明确故障注入，工具超时是在真实只读查询后丢弃回复，不意味着工具未执行。

仅准备本地 pending 审批，不批准、不发送。人工拒绝、过期、修订、并发审批继续由 Day 81 验收，不属于这个适配器；真实模型、真实通知、任意 SQL、跨会话 Memory 与季度 Planning 均未覆盖。

Day 85 旧示例继续由旧契约读取；本集使用新 `1.0-dataset` schema 和 Day 86 CLI。改变场景、期望或源文件应升级数据版本、重新审核和执行；不得为了通过测试直接改成观察到的错误答案。来源摘要按 UTF-8 文件的 LF 内容计算，摘要只检查一致性，不证明作者身份。
