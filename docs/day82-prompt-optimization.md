# Day 82：优化 Agent Prompt

按 Week 12 路线，在固定销售查询中减少模型猜测、范围偏移和错误字段映射的机会，并建立可以复跑的对照入口。本日交付候选 Prompt 与评估工具，没有宣称已经测得模型幻觉率降低。

## 实现

- 独立的 [候选 Prompt](../experiments/day82/candidate.md)：划分调用工具前后两个阶段，按回执逐字段填写报告，强调全量金额、明细截断、无数据、来源引用和审批边界。
- [注入适配器](../experiments/day82/prompt_policy.py)：保留宿主校验与模型输出，只在转交模型时替换 system 内容；记录版本摘要和实际输入。
- [对照与集成入口](../experiments/day82/prompt_lab.py)：基线/候选使用相同场景，交替运行顺序，每例独立会话；可选真实模型对照有总请求上限，无自动重试。
- 新版 `prepare` 复用日志、错误恢复与待审批流程；没有自动批准，也没有对外发送。
- [16 个固定样例](../experiments/day82/cases.json)和[可复刻教程](../experiments/day82/README.md)。

## 本次验证

60 项新增测试与 518 项既有回归，共 578 项通过，无失败、错误或跳过。其中：

- 16 个样例 × 2 个版本 = 32 次脚本回放，正常结果通过、错误结果被正确拒绝；这些回放是新增测试的一部分，不额外累计为 32 项独立测试。
- 新版集成 9 个组合：全客户/指定客户/无数据/澄清、只读重试、重试耗尽、报告降级、错误报告及错误参数。成功后保持 `pending` 且模拟发送记录为零；失败不创建审批。
- 反向测试检测错金额、客户、引用、虚构标记、数据库变化、调用次数与状态；另验证输入不可变、输出目录保护和请求预算。
- 既有回归包含 Day 81 的完整 15 个业务场景；它仍调用既有流程，不等于 15 个场景全部替换成新版 Prompt 后执行。
- Ruff 与 v0.5/v0.2/v0.1 冻结资产完整性检查通过。旧实现与旧发布证据保持原样。

机器可读结果：[validation.json](evidence/day82/validation.json)，双版本报告：[report.json](evidence/day82/comparison/report.json)。完整实际输入、输出和回执按报告中的相对路径定位；本次 JSON 证据均使用虚构资料。

## 结论与边界

两版在离线回放中获得相同的脚本输出，因此全部通过验证的是宿主控制与新版接入，不是模型理解 Prompt 的能力。`prompt_quality_comparison=not_measured`；本次真实模型请求为 0，真实消息发送为 0。新增测试中的 live 调度测试使用替身，不属于真实 Qwen 证据。

候选只在 Day 82 入口使用，未替换 Day 73 或 Day 80 默认 Prompt。下一步可以手动运行真实对照：每版最多两轮，单个样例最多 4 次模型尝试，全套 8 个适用样例最多 32 次。应依据错误明细和重复实验决定是否采用候选，不能把服务超时或小样本波动直接归因于 Prompt。

固定查询、虚构数据、宿主机 CLI 和本地审批模拟等既有边界不变；没有新增任意任务规划、真实发送或身份认证。Day 83 Demo 可以展示新版生成 → 回执校验 → 待人工确认的可观察过程，录制工作另行进行。
